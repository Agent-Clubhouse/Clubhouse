# Dispatcher durable context contract

Instruction generation always starts from shipped role text, the role's skill directory, and the existing user name/personality. It never reads the previous instructions file as input. Providers replace their conventional instructions file; they do not append. Preserve the existing normalized user name and the stored personality text verbatim. The name/personality settings, their limits and permissions are unchanged.

The built-in role plus its skill directory is limited to 16 KiB UTF-8. Exceeding that bound is an explicit generation error, never silent text truncation. The separately appended user text is not trimmed to fit this budget. The existing stored personality limit is 2,000 UTF-16 units; source tests measure complete generated instructions including custom Unicode text and the fixed lookup. This is a file-generation bound, not a claim about total model context or external file writers.

Detailed management procedures live in the managed `tool-procedures` skill. Its procedure body is the original Act section, preserved verbatim. The compact role keeps authority, ownership, identity, human/app/host approval and interruption constraints and requires the full relevant guide before actions. Missing guide means report the blocker, not guess or bypass. All other built-in skills keep their existing provider delivery and user-file preservation rules.

Mutable memory never becomes an instructions snapshot. A fixed lookup requires `read_memory` at task entry and the relevant current pages before acting; missing memory is missing context, not approval. Active decisions, user constraints, topic provenance, custom text and history remain in their existing files. This change performs no semantic selection, compaction, live rewrite, or deletion of those files. The existing lossless notes migration remains in generation.

`search_memory` gains an explicit `history` scope. It searches only retained markdown versions under `memory/history/`, returns paths for existing `read_memory`, and never queries transcripts. Default `all`/`memory` searches continue excluding history, so obsolete facts cannot silently rank as current. Existing page, snippet, query and result bounds and symlink exclusions apply. Retention stays five observed versions per page for up to 30 days; this does not promise unlimited history, recover unseen edits, or authorize an agent to edit history. Topic/archive/transcript search remains available under its existing scope and limits.

Recurrence controls are a measured shipped-context budget, fixed memory-lookup output across repeated updates, and explicit instructions to keep plans/reports/detail out of the generated file. Arbitrary external file edits remain possible under existing filesystem access; this adds no permission boundary or live file watcher. No automatic re-generation/restart is introduced.

Validation must exercise real temporary memory writes, current and retained historical reads, repeated generation and provider replacement, exact custom text, UTF-8 boundaries, actual managed guide delivery, history isolation and symlink refusal. No live Dispatcher files or private evidence belong in tests or public source. Independent exact-source/evidence review precedes any PR.

## Explicit product disposition and delivery failure

The parent owner explicitly retains pull-only current context under the user's compact-context and on-demand-history redesign. Canonical active decisions stay in memory; the fixed mandatory lookup remains instead of restoring an 8 KiB snapshot. Core authority and stored user text stay inline. Tests establish the written contract and retrieval, not that a live model actually performs the required reads. Observed 32 KiB delivered records do not establish a universal provider limit or justify an embedded snapshot.

Required skill delivery must succeed before publishing a new instructions root. Missing provider conventions and partial/failed skill writes reject, preserving prior root bytes and the original error. This is not an atomic root/skills transaction: previously delivered skills can already have changed or disappeared when a write fails. The existing startup refresh fallback can use its previous file, which may be compact or stale and may reference unavailable guides; it is not guaranteed to contain old inline procedures. That unchanged runtime policy is not broadened or certified here. A missing guide still requires reporting the blocker before action.

Historical snapshot reads do not update the bounded active-page access record, whether through history search or explicit page reads. Although upkeep's page lists already exclude history, shared access-record capacity could otherwise evict current-page metadata and affect neglected-page decisions. Existing access records and retention are left untouched; this is no live rewrite or repair of earlier evictions.
