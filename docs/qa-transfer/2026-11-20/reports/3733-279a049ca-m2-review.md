## Source

- **The callback:** `RemoteHelpersCard` gains `onRefused?`, held in `useRef` and updated on every render, so the **latest callback** is used.
  - It is called only when `active && result.status === 'forbidden'`. The effect cleanup sets `active = false`, so an **unmounted or superseded read never signals**.
  - Only `forbidden` signals. Errors, offline, unavailable and rate-limited do not.
- **Wiring:** both call sites in `RemoteAgentDetailsView` pass `onRefused={() => setRetry((n) => n + 1)}`. They are the sleeping-inline `helpersOnly` portal (:195) and the Details-column card (:216), the same pattern as Actions, Managed and Canvases.
- **No retry loop:**
  - A page read happens only for a user `selected` page; the overview needs no read. The selection identity includes `freshnessKey`, which derives from `refreshKey` and so from `retry`.
  - After `setRetry`, the selection resets to the overview and the refused page is **not re-requested automatically**.
  - If the central re-read is itself forbidden, `eligible` becomes false and no page reads happen.
- **Admission is not weakened:** `eligible` (connected, snapshot available, status ok, matching agentId) and the `helperPages === 1` gate are unchanged.
