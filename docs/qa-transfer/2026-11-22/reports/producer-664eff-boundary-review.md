## Compatibility constraint: MCP entry gates remain entry gates

`clubhouse-mcp/mcp-call-gate.ts:1–18` explicitly says **“A call already running finishes. Nothing here stops an agent.”** `mcpCallAccess` at38–44 is used at tool-registry entry; `forgetMcpCaller` at103–108 changes future caller bookkeeping. Do not add a post-await `mcpCallAccess`, `mcpCallerKind`, tool-list membership or global epoch veto that turns gate closure/forget alone into cancellation of a running tool. Do not invalidate on every undifferentiated tool-gate notification.

This does not grant the operation an indefinitely valid handoff permission or authorize a new source. Actual current handoff grant refusal, lost required handoff connection, a changed original source/target identity, or retirement of the captured handoff host before **domain admission** can refuse this handoff's effects. Existing `callerGrants` derives helper/default rights from current state, so forgetting can have a real grant consequence in some contexts; that must be evaluated by the existing domain grant checks, not equated to a new global cancellation rule. The matched forget-only control should preserve the relevant domain grant/source/host unchanged; it must not assert that every concurrent permission mutation is benign.

Preserve all unrelated tools and standalone preparation behavior. No native-request signal or runtime-generation/coordinator is borrowed as MCP-call cancellation authority.

## Required original-context capture and minimal private seams

Treat the in-process captured invocation as a **negative continuity and identity witness**, not new permission. It must never be serialized in offers, cached as authority, accepted from tool args, or used to bypass full grants.

1. **Start before automatic preparation and retain the exact host.** In the offer tool's existing entry path capture an immutable copy of authenticated agentId and original localized call arguments; capture the original host object/machine and register the actual producer operation before `ensurePreparedHandoff` starts or waits another preparation. Resolve/validate the intended target and registered source under that capture. A later `handoffHost()` must not silently replace the original host after Git, source resolution or queue waits. Initial async module loading is not a committed offer; the contract must name when host capture begins and must not claim a host was captured before it actually was.
2. **Freeze the canonical recipient as well as approval arguments.** Keep `record.to` immutable and compare the full positive authorization's resolved target identity to that exact recipient. Current `handoffAgreementCallApproved` re-resolves original alias arguments, whereas the record target was resolved earlier. Its Boolean alone does not establish those resolutions coincide. A renamed/retargeted alias must not lend approval forB to the already constructed offer forA, or cause recapture/adoption ofB. Keep original args unchanged for the consumed-approval key/context; do not canonicalize them into a different call after approval. Current connection/Dispatcher/project facts still come from the existing positive authority rules.
3. **Freeze the source and exact catalog entry.** Use the original owner, machine, registered project identity/path, selected worktree identity and existing bounds/secret policy to prepare/validate bytes. Capture a main-only preparation selection identifying the exact catalog entry ID, owner/project/mode and immutable summary. On binding validate that entry, TTL and original source; never select a new caller source/project or an interchangeable same-summary entry just because later lookup succeeds. A new preparation/removal or incompatible source change can cause safe failure; it cannot silently authorize a replacement. No user-supplied path or new durable preparation schema is needed to achieve this with private arguments/closures.
4. **Scope continuity to handoff authority/source identity.** Capture before relevant awaits, check after them, and retain invalidation for actual relevant revoke/restore or host/source retirement. Reuse suitable existing revision/notification mechanisms with specific predicates, not a generic cancellation framework or arbitrary registry object equality. A durable caller need not still have a live runtime merely to finish a call if its original registered source and current handoff rights remain valid. Cosmetic labels, unrelated target bindings or generic gate-close notifications are not new domain authority facts. Do not present the existing `transferAuthority` unchanged as sufficient producer authority: it is a negative lease for later transfer/sync, not the original call's full positive/consumed-approval proof or preparation-selection witness.

**Minimal surface recommendation:** keep the existing four private files (`handoff-service`, `handoff-coordinator`, `handoff-preparations`, `handoff-host`) and include the already provisionally allowed `clubhouse-mcp/tools/handoff-tools.ts` for pre-preparation capture/ownership. For recipient correspondence, a narrowly scoped addition to existing `clubhouse-mcp/handoff-permissions.ts` is justified if needed: compare its resolved handoff target to the expected immutable record target while retaining original args, current evaluator and consumed context. This is a concrete private handoff dependency to disclose in the implementation freeze, not permission to rewrite `tool-registry`, `grant-check`, `mcp-call-gate`, approval storage or shared store helpers. An equivalent demonstrably race-free original-target check within the five files is acceptable; a separate earlier alias check with an unguarded later re-resolution is not equivalent. The exact chosen interface/hunks still require source/proof review before PR.

## One admission point and truthful independent saves

**Choose the actual history transaction's queued callback, after duplicate/capacity preconditions, fresh complete positive authorization for the original call/actor/record/recipient, and a final synchronous original-context continuity check, immediately before the first offer-specific durable write.** The prequeue positive check can remain as an early refusal; it does not replace this queued admission. Any await in reauthorization/source verification must end in that final check. Failure/throw/negative authorization before the point must not reach the marker, bind, history, offer notice or outbound synchronization.

At that instant admit the fixed offer ID, first history operation ID, original host/source/preparation selection and record as one local workflow. This admits its ensuing independent command/catalog/history work; it does **not** promise those files commit atomically. The same captured values flow through every queued stage. Do not insert a later liveness check that abandons an already committed catalog binding while reporting a global no-effect refusal, or set an admitted flag only after the first save. A two-stage alternative must be specified and proved separately rather than silently changing where admission occurs.

| Timing/outcome | Required truthful behavior |
|---|---|
| Retirement before domain admission, including while waiting history queue or positive authorization | Refuse this offer before offer-specific marker/binding/history/publication. Already authorized local snapshot work or separately admitted maintenance may have written; this is **not** a global zero-write guarantee. |
| Admission succeeds, then retirement while a command/catalog/history queue or save is pending | Already admitted local persistence may finish. Successful individual saves publish their matching in-memory committed snapshots. Do not fake a rollback/refusal after successful history save. Host replacement waits actual owned work. |
| Marker succeeds but binding fails, or binding succeeds but history validation/save fails | Preserve exact original IDs and actual per-store outcome. No fabricated history/offer/notice/success; no cross-store deletion or compensation merely to make the result look atomic. Existing orphan/preparation retention/pruning semantics remain explicit. |
| An IO failure may have committed despite throwing | Report/retain uncertainty, not “no write”, “never offered” or a retry authorization inferred from stale in-memory absence. Preserve original error/evidence and distinguish deterministic prewrite failure from ambiguous after-write/rename failure. Do not repair shared persistence opportunistically. Broader recovery guarantees would require a separately reviewed scope. |
| History save succeeds | Retained history is genuine and follows existing normal notice eligibility, including later sweeps; it is not a call-specific final-sink receipt. A changed original call does not retroactively erase it. |

Coordinator's existing initial prune and independently authorized explicit `prepare_handoff` are not offer-specific binding. Their already admitted effects are excluded from a zero-effect claim. Implicit preparation may leave an unbound prepared snapshot if retirement happens while it is doing already started authorized local work; never describe a failed offer as proving no local IO. Its creation/cleanup stays within existing TTL, quota, path, secret and ownership rules. If the implementation chooses a stronger stop-before-new-preparation boundary, name and test it without rewriting standalone preparation authorization.

Keep later transport admission separate: a committed offer is not itself permission to initiate a fresh POST after host retirement. Finish or skip the immediate synchronization leg truthfully using existing original-host/current-authority checks; retain the committed offer for normal later authorized synchronization. Do not retroactively report successful persistence as failure merely because the initial sync is unavailable. Do not expand this into a rewrite of accepted native/reverse command, cancellation, delivery-marker or retained-history behavior.

## Actual operation lifetime, retries and failure constraints

Register a per-invocation producer owner on the captured host before implicit preparation and any dependent store waits. Hold it through the **actual** Git/preparation/catalog/history/coordinator operation and any already launched owned continuations, not just a deadline or caller waiter. In `finally` release exactly once on success, refusal and error, disposing listeners only after their last use. `stopHandoffs` closes new domain admission, retires captured producers and waits their actual settlement; host replacement must see those owners as well as the existing reverse/incoming sets. A deadline can end a waiter without proving the actual work finished. Do not release ownership on `Promise.race` alone.

Avoid a stop cycle: an owned producer must not await the `stopHandoffs` that is waiting it, recapture/create a replacement host, or require an owner-disposed listener to release its held save. A stop test must release held actual work while observing stop still pending; it must not simply await stop before releasing the dependency. Do not drain all legacy/local preparation or other tool calls globally. If a prior standalone preparation is a dependency, the implicit producer owns its await/continuation; this does not create a new cancellation authority for that separate explicit call.

The current local `service.offer` generates a fresh agreement ID and first operation ID **per new invocation**; `callKey` identifies approval arguments and is not a durable offer idempotency key. Existing synchronization retries replay the same already persisted immutable agreement. Preserve that distinction: no automatic recapture/reprepare/new-ID retry after partial durable failure, lost reply or unknown outcome; no exactly-once claim. A later explicit new invocation can make a distinct agreement under current rules. Existing query/history and generic sanitized error must not be presented as evidence of absence. Preserve same record/manifest/entry/IDs across phases, existing remote `undelivered` versus `attempted` semantics, never-attempted cancellation behavior and eventual normal history/prune processing. Do not introduce a new cross-store repair, wire field, tool schema or retry protocol as part of this slice.
