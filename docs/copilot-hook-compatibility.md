# Copilot hook and permission compatibility

Clubhouse allow/deny project-default rules use a different schema from Copilot's hook documents. They are not translated into Copilot grants or denials: nonempty rules stop Copilot materialization with an actionable error before any defaults are written. Remove or change those defaults and configure the intended access using Copilot's native controls before restarting. Free Agent Mode and the chat permission callbacks remain separate capabilities.

Copilot discovers `.github/hooks/hooks.json` even when Clubhouse's hook server is off. Clubhouse checks that file before launch; an absent file is allowed, while malformed JSON, a document lacking `version: 1` and a `hooks` object with event arrays, invalid or unrecognized hook entries, or a document containing `permissions` stops startup. Unrecognized future hook types are left untouched and require review rather than being rewritten. Clubhouse does not replace or remove ambiguous files. If a legacy file contains only unintended permissions, review and save the contents, configure any intended access through a supported mechanism, then remove or repair the file and restart. Preserve any custom hooks and other content. A permissions-only shape has no ownership marker and is not proof that Clubhouse created it.

| Runtime | Clubhouse hook server | Callback path and limits |
| --- | --- | --- |
| Terminal | On | Clubhouse merges command hooks into the Copilot hook document, preserving custom entries and replacing its own entries on repeat writes. Hook changes require restart. |
| Terminal | Off | Clubhouse does not inject command hooks. Existing custom hooks remain Copilot's configuration. |
| SDK chat | On or off | Clubhouse uses the SDK event and permission callbacks, not its terminal hook injection. Configuration discovery remains enabled. |

Chat startup refuses a hook document containing marked Clubhouse terminal callbacks, because those callbacks can overlap chat's protocol events. Stop the terminal agent and remove those marked callbacks before restarting chat; custom hooks are left intact. Disabling the hook server removes recognized Clubhouse entries from stopped agents and preserves a valid empty Copilot hooks object when needed. Conflicting permission documents are not rewritten.

The tests exercise synthetic files and mocked callbacks. They do not establish behavior for every Copilot CLI version or prove runtime delivery. Copilot's documented hook structure and restart requirement are described in [GitHub's hook documentation](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks) and [hook reference](https://docs.github.com/en/copilot/reference/hooks-reference).

Cleanup validates the entire current Copilot document before any rewrite, including on normal exit and application quit. Malformed, unsupported, unreadable, and conflicting current files are retained for manual repair even when an older snapshot exists. Successful cleanup leaves a valid `hooks: {}` when no callbacks remain. Other providers keep their existing recovery behavior.

Copilot ownership requires the entire generated entry: exactly `type: 'command'`, the generated `bash` curl callback with the agent-ID and nonce-header environment markers, and `timeoutSec: 5` (`120` for `permissionRequest`). Current environment-port and historical fixed-port forms on POSIX and Windows are recognized. Extra fields (including another command, environment, or extension), changed or missing timeouts, and unknown marked forms make the entry ambiguous; the whole document is preserved for manual repair. A custom command containing `/hook/` alone is never ownership evidence. Older forms without recognizable markers cannot be safely attributed automatically. Review those files explicitly before moving between terminal and chat. This is a compatibility boundary, not CLI delivery proof.

Live Copilot chat registrations are excluded from terminal-hook toggles, including their permission queue and MCP snapshots. Their working directories remain excluded from stopped-agent reconciliation. If terminal cleanup or injection requires repair, the toggle sends an actionable notice through the existing runtime-notice channel and does not report that agent as successfully reconciled. It never restarts an agent automatically. Cleanup on exit or quit logs repair requirements; the next launch still refuses an ambiguous hook file.
