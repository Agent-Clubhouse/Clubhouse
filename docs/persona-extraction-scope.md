# Persona extraction scope (#2850)

Extract captures files, not a running conversation or a provider's full effective context. It inspects the provider's primary worktree document. For Copilot it also captures root AGENTS.md, CLAUDE.md and GEMINI.md, in that deterministic order after .github/copilot-instructions.md. Each captured source is named in the preview; multiple documents have provenance headings in the exported body. Identity values are re-genericized, with custom text retained. No assigned persona is required.

Copilot documents these root files in its [custom instructions guide](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions). This export does not resolve ancestor/user instructions, nested/path-specific rules, @file references, environment-selected directories or session context. The dialog states that limitation and requires review of the bounded capture before Save; it does not promise equivalent runtime behavior. Users can edit the preview deliberately before saving. A failed read blocks export instead of presenting a savable empty body. A legitimately empty capture remains distinguishable and can be saved after review.

The additional reads are fixed named root documents, not recursive inventory or arbitrary imports. Links, non-regular/oversized files and observed changes are refused. These checks do not establish whole-path atomic confinement against concurrent parent replacement, nor release the separate inventory security hold. No global or external instruction files are traversed.

Synthetic regression coverage uses a Copilot source with no persona, a primary identity document, root custom instruction markers and a distinct destination. It calls Extract, saves the actual persona file and calls Apply with Clubhouse Mode off/on, checking actual destination .github/copilot-instructions.md bytes and unchanged source text. It also checks primary/supplementary read failures and the dialog's refusal to save failed extraction. This is file delivery evidence, not a real CLI/load/session test.

The round trip exposed an existing materialization defect: persona-only and appended persona bodies were written without resolving identity wildcards in Clubhouse Mode. These branches now resolve them just as Apply outside Clubhouse Mode does. Existing sessions, provider selection, permissions and source documents are not changed by extraction.

Builder/activation acceptance must retain this no-persona/multiple-source/custom-marker case. Saved Builder composition, this bounded file capture and native runtime composition are different scopes; none should silently stand in for another. No new import, assignment, lifecycle or Dispatcher grant is introduced. #2855 remains a separate scoped proposal.
