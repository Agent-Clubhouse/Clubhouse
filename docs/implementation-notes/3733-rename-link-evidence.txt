Source: read-only-repository-changes.ts derives a regular-file match from existing
immutable tree OID/size/mode and already-compared raw worktree bytes. Exactly one
prior source and one observed addition must match. No fuzzy/similarity matching
is added to live Branch/Session/Last-turn reads. Saved-turn Git rename evidence,
including edited-file counts/text, retains its existing implementation.

Live list pairing requires a complete eligible bounded inventory with no unknown
added endpoint. Private/cut inventories, duplicate prior content (including private
copies), duplicate added destinations, edited/filtered/binary/unsafe/mode-uncertain
endpoints stay unpaired. At most 32 candidate pairs receive endpoint rechecks,
which consume the existing remaining total-content budget. Source absence is
checked with the existing zero-byte no-follow reader, destination raw bytes/mode
are reread unchanged, then source absence is checked again. No new external
program, Git write, filter execution, network, grant or link-target read is added.
The existing check-attr invocation also checks the selected source on rename-open.

The same 64-hex opaque query shape binds both source and destination with two
128-bit endpoint tags derived from the existing comparison-scoped keys. Lookups
must uniquely identify both endpoints and refuse ordinary/rename ambiguity;
these are selection witnesses, never authorization. Opening re-derives the exact
unique prior source and rechecks both endpoints. A replaced source, destination
edit/removal/mode change or substitution to a different prior source returns stale;
a newly filtered source stays refused. Every awaited read still checks authority;
the outer selected agent/root/HEAD/run/session/native/target witnesses are unchanged.

Paired rows show sanitized old/new labels, zero line edits and an authorized rename
notice on open. Aggregate diffstat/pagination use the represented rows. Unpaired
additions/deletions retain their own counts; no missing count becomes zero.
An existing equal-bytes shortcut now also checks side presence, so empty-file
add/delete/move paths survive as known zero-line changes instead of false empty.

Link-own metadata: explicitly REFUSED under the current passive contract, as the
parent directed. No readlink call, symlink blob admission or target dereference is
introduced. Changed live/saved links retain unsafe evidence and unknown line
counts. UI states that destinations are not shared and target contents are not
read; it invents neither a destination nor zero known line counts. This display
gap remains a contract limitation, not full local link-metadata equivalence.
