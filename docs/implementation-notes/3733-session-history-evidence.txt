Scope and gate

Optional chatPage.historyBinding is emitted only for an existing ordinary durable
live chat on the already-authorized desktop path. Direct and tracked Quick IDs,
Dispatcher/controller identities, phones and unconfirmed/older runtimes receive
no positive history receipt. Existing query inputs/grants/role routes are unchanged;
no Details or Details-query schema file was edited. The isolated additive schema

The receipt contains projectId/agentId/sessionId/providerId/driver/nativeSessionId/
displayRunId/startSeq/subagent capability, never paths, raw configuration or launch
nonces. It requires the admitted project's registered primary inventory and exact

and valid existing runtime display evidence. Its private primary witness and
runtime/registration/nonce/provider/native/open-generation/start sequence are
checked after awaited page work. Revocation remains403; changed target/runtime409.

Client and display

The existing transcript read retains its actual nextBeforeSeq and validated receipt
internally. Inconsistent/missing cursors remain unknown. Older history reads happen
only on an explicit button press through annexClient.chatPage, one requested200-event
page at a time. A maximum2000-event transport envelope and conservative8MiB string
estimate are checked; oversized/malformed pages are refused, never silently cut.
Only one archived event page plus at most32 cursor breadcrumbs are retained. Newer
navigation rereads a page; there is no full-history fetch/accumulation loop.

Every accepted page must echo the same selected host transport/project/agent/session/
provider/driver/native/open generation/start sequence/capability and a descending
cursor. Events must belong to that exact agent/session, be ordered below the cursor,
and agree with any reported root provider/native identity. Events before startSeq
are excluded; reaching that floor or cursor end is not complete resumed history.
Selection/snapshot/transport/receipt revision changes discard late responses. A
denied/error page immediately withholds earlier archived evidence; no local-chat,
Quick, controller or stale-private fallback exists.

Archive summaries never overwrite the live chat store or current recorder facts.
Full/ids_only/none remain distinct: ids_only hides names/status, none does not infer
zero children. Report and name lists have explicit50-row navigation, including the
65th child/skill when recorded. No cap64 recorder completeness is asserted. Provider
report identity/source is checked; absent versus explicit-empty versus malformed
lists remain distinct. Shortened/omitted events stay partial. Tool activity/duration
is attributed only where this page records the child relationship; missing starts,
tokens, cost, scope or totals are not fabricated or added across pages. Known0 stays0.
