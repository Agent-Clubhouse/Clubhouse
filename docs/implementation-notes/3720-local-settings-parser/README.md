Source freeze: `b908917305eaea9d2b8a11030e2361830b1478b9` on `annex-wake-readiness/3720-local-settings-parser`, based on main `e8e178c4bf462bcf443bfb1b91cbfbcd1f35d1c2` (landed launch utility). Canonical issue: https://github.com/Agent-Clubhouse/Clubhouse/issues/3720.

This piece adds only the pure `src/shared/annex-settings-ipc.ts` patch/Edit types and parser, behavioral tests, and the proof recorder. No consumer imports it yet. IPC/preload/store/renderer, filesystem/runtime/launch consumers, network/mobile codecs and naming persistence/activation are unchanged. Real sender/frame/document, grant, current epoch and committed-field conflict checks remain future admission responsibilities; a syntactically valid origin, ID or counter is never authority. Committed snapshot/result types and handlers are deferred until their actual implementation piece.

The parser accepts only explicit changed or unset fields and their exact version union. It validates the closed descriptive origin/key combinations, UUID-v4 epoch/request IDs, safe counters, well-formed UTF-16 and per-field limits. It rejects extra own keys (including symbols/nonenumerable properties), accessor descriptors, custom prototypes, sparse/nonplain arrays, duplicates and set/unset overlap, without reading raw getters/iterators. It constructs detached typed data and enforces the canonical UTF-8 JSON cap. Whitespace, empty strings and custom icon/color identifiers remain intact. Name publishing trim/effective-name rules are deferred, not silently introduced here. Same-value writes are valid input; version increments/conflicts are not performed by this parser.

Small implementation refinements relative to the reviewed scaffold: ES2020-compatible own-property checks, frozen exported editable-key list, an early object-key-count bound, exact 36-character UUID length (the JavaScript `$` anchor alone permits a final newline), and normalization of *all* errors thrown while reflecting on raw input. A direct Proxy could throw an exported parser-shaped error; the scaffold-style outer `instanceof` catch alone incorrectly retained its unsafe request ID. The new dedicated reflection boundary converts it to a fixed `invalid_envelope` with null request ID.
