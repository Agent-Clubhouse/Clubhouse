The native passthrough is `new Proxy(actual.execFile, { apply(target, thisArg, args) { ... } })`: only the apply trap observes the call, with `Reflect.apply(target, thisArg, args)` executing the original exactly once. It forwards the same `this`, argument identities, options, callback and returned `ChildProcess`; synchronous throws propagate unchanged. No property/prototype/construct trap: native own descriptors, prototype/name/length and `Symbol(nodejs.util.promisify.custom)` forward unchanged, without `vi.fn`, callback replacement or a generic promisifier. The original custom promisifier is retained, not newly instrumented; the inspected tracking call is callback-based. Exported function identity and `Function.prototype.toString` representation differ from the original, so do not claim universal reflection equivalence. Every late native/body completion captures the original recorder, never a subsequently active case. Frozen records explicitly remain incomplete; late completions cannot overwrite another case or be represented as observed completion.

This does use Vitest module interception to access an otherwise closed-over native import; it does **not** mock Git execution or tracking results. Independent design assessment must explicitly accept this native-only seam. If even passthrough interception is disallowed, there is no fixture-owned asynchronous seam in this source: report that limit instead of adding a production hook or pretending outer delivery timing identifies Git.

Every observer operation (begin/end, clock read, close-listener attach/callback/detach, raw/console write and freeze/serialization) is best-effort and nonthrowing. One small fixture-local containment boundary may catch only diagnostic operations, never `Reflect.apply`, an original callback, original assertion or `stop()`. Native execution remains unconditional and exactly once, outside that boundary; its original return/throw survives even when observation fails. Original `finally { stop(); }` remains unconditional and cannot be skipped or masked by observer cleanup. Capture a separate recorder per invocation, detach only owned listeners and never resample the active recorder from late callbacks. Stop accepting events before detach, prepare the bounded immutable snapshot/string and release owned references before final emission; after freeze, no event, failure counter or late callback may mutate that recorder. Final output/timing uses prepared strings and local emission status, not mutable frozen-record state.

Observation failures set explicit bounded `observerFailures`/`observerUnavailable` fields, with no error payload. Subsequent available channels report those fields; failed serialization may emit only the fixed `{"version":1,"observerUnavailable":true}` envelope. That is unavailable diagnostic evidence, not successful measurement or an application result fallback. No recursive logging/retry, process-wide error handler, altered runner state or private task-log/artifact write. If both output channels are unavailable, retain the primary outcome and claim no observation proof.

## Durable, bounded, payload-free output

Each begin/end and abort/final snapshot is a small `process.stderr.write` line prefixed `CLUBHOUSE_MANAGED_PHASE_V1 `. Emit begin before native calls: a synchronous stall can leave a last-started phase in raw output even if the timer cannot fire yet. Use a monotonic clock, relative offsets, static phase labels, sequence numbers, completion/throw booleans and active-phase elapsed intervals. Retain the abort snapshot separately from the final snapshot so later cleanup cannot erase evidence that work was unfinished at the deadline. Cap both retained transitions and raw transition emission at 32; drops only update bounded accounting before freeze, not emit per-drop lines. Allow at most one abort, final, overflow/unavailable notice and console-emission status line per recorder. No post-freeze or per-failure output loop.

The final `console.error` receives a fixed prefix and the prepared JSON, not objects/native values subject to console inspection. It contains the bounded event history and both snapshots. Pinned Vitest 4.1.12 JUnit defaults `includeConsoleOutput` to true and serializes captured stderr task logs into `system-err`; the baseline uses existing default+junit reporters without a silent override. This is source-level feasibility, **not executed failure-channel proof**. A returning console call observes emission only, **not durable acknowledgement**; actual raw/JUnit output must be inspected. Raw stderr is the early channel; the existing uploaded JUnit artifact is the final durable channel when hooks/reporting finish. A killed worker/job may have only partial raw transitions: no final record or duration is invented.

The fixed phase set is `beforeEach`, `seed.copy`, `builtins.ensure`, `body`, `git.init`, `git.add`, `git.async`, `delivery`, `resolve` and `grant.cleanup`. Transition fields are `seq`, `event` (`begin`/`end`), `phase`, `offsetMs` and `threw` on an end. Snapshot fields are `event` (`abort`/`final`), `offsetMs`, `aborted` and `active` entries containing only `beginSeq`, `phase`, `startMs`, `elapsedMs`. Final JSON keys are `version`, `platform`, `node`, `transitions`, `abort`, `final`, `overflow`, `droppedTransitions`, `observerFailures`, `observerUnavailable`; absent abort is explicitly `null`. A best-effort raw `console.emitted` event reports the returning console call's `offsetMs`/`elapsedMs` separately, without asserting durable publication. Completion means a scope returned/child closed, not Git success or grant delivery.

The allowlist is the fixed diagnostic version, `process.platform`, `process.version`, static phase/event labels, finite relative numbers and booleans. Never serialize native arguments/options, cwd, paths, environment, project/agent/task identities, contents, stdout/stderr, errors/stacks/reasons or child identifiers. Any overflow must be explicit, not reported as a complete trace. Console emission time is diagnostic overhead, not delivery/body time or artifact acknowledgement; phase measurements are instrumented wall intervals, not pure subprocess/CPU attribution. Both inline logging overhead and changed scheduling may affect this new observation; even a green run does not retrospectively prove a flake or remove the original failure.
