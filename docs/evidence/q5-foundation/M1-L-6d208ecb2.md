## Implementation and limitations

Both fresh-metadata and active-marker writes share an exclusive-create temp
scope. Finally closes the writer and best-effort removes only the current
attempt's created temp, with inode/device identity comparison when available.
It never removes the final metadata path, arbitrary prefix matches, foreign
replacements or files from an earlier process. Write/sync/rename failure keeps
its original cause; secondary close/cleanup errors do not replace it.
The cause is private/non-enumerable, so normal JSON failure serialization omits
raw paths. Stable code/message handling remains unchanged.

Injected ENOSPC across markerCreate/envelopeCreate/markerActivate and EIO around
write/rename clean the own temp and allow reopening; committed bootstrap UUID
is retained. An actual rename failure induced with a conflicting directory
cleans the own temp while preserving that directory. Injected cleanup failure
retains the first ENOSPC and leaves its residue refused on reopen.

An **actual child process exits77 after envelope temp creation and before write
or rename**. Finally cannot run. The next open preserves that temp/marker and
fails closed. No exact-prefix recovery/deletion is implemented or credited;
crash or failed-cleanup residue may require inspected manual recovery. Marker
temps outside the ledger directory remain inert if a process dies before cleanup.
This does not authorize broad cleanup or promise automatic recovery of every
interrupted filesystem state.

New controls also cover phase/version/UUID mismatch, envelope-as-directory and
envelope symlink. The symlink control executed on this Darwin host; on Windows
with an actual EPERM/ENOTSUP/EACCES native fixture refusal it explicitly skips
without asking for new access. There is no native Windows or power-loss credit.
