# Architecture-to-test map for push/PR shadow selection

Source baseline: `817ef3827c266dab9fef40c9ab06cd23d06fb394`, inspected 2026-11-23. This map proposes **shadow reporting only**: existing CI remains authoritative, no workflow changes or activations, no release work. The selector helper owns algorithm implementation through the Orchestrator; this lane owns the architecture evidence and eligibility limits. A changed directory name is not an isolation proof.

## Architecture and test ownership

| Boundary | Actual runtime/build coupling | Current proof and selection consequence |
|---|---|---|
| Main bootstrap | `src/main/index.ts` imports services/IPC/protocol setup; literal dynamic imports start managed migration, app-event sources, Actions, Dispatcher background and Git watcher. `require('electron-squirrel-startup')` participates in Windows startup | `main` Vitest project includes **both** `src/main/**/*.test.ts` and `scripts/**/*.test.ts`; much Electron/child-process/network behavior is mocked. Keep bootstrap, lifecycle, service registries and IPC ineligible for initial reduction; an import-free handler edit can still affect globally registered behavior |
| Renderer roots | `src/renderer/index.ts` chooses App or PopoutWindow, installs telemetry, exports React globals for community plugins and imports CSS; stores/plugins and UI shells are shared | `renderer` uses jsdom and global setup mocks; UI file closure can reach App/Popout and many tests. Keep bundling and existing Linux/Windows E2E as independent proof, even for a selected unit cohort |
| Shared | Runtime functions, type contracts, IPC definitions and serialized remote/mobile messages share this directory. `theme-colors.ts` imports renderer theme constants and is used in main `active-theme-store.ts` as well as renderer themes. `git-branch.ts` is type-only and imported by main, preload and renderer | `shared` is a Node Vitest project, not an isolated product layer. Type-only edits still require full typecheck and contract review; runtime/shared changes do not qualify initially. Do not classify all shared functions as OS-independent from folder placement |
| Preload | `src/preload/index.ts` spreads many bridge modules; computes settings channel names with `settingsChannels(key)`; exports `ClubhouseAPI`; reads process platform/argv and exposes contextBridge. Renderer invokes bridge methods instead of importing main handlers | `preload` project tests plus `shared/ipc-channel-sync.test.ts` and `main/ipc/index.integration.test.ts` cross the boundary. A TS dependency graph cannot infer an invoke/channel string to handler edge. Treat every preload, IPC, settings-definition and API type change as full fallback |
| Native/process | Main pty-manager imports external `node-pty`. Postinstall `scripts/fix-node-pty.js` chmods Darwin spawn-helper and patches Windows build files. Forge stages node-pty and transitive dependency directories from installed package metadata; excludes SDK runtimes/FFI | Mocked unit tests do not prove the real native module starts. Keep dependency/install/packaging/native helpers ineligible; retain real Linux/Windows build/E2E, Linux glibc/package checks when already selected, Windows packaged startup and current Mac pause/override semantics |
| Build | Forge combines main, renderer and preload entries. Renderer webpack config mutates shared `rules`; ForkTsChecker and Monaco plugins are shared. `ts-loader` transpiles TS; copied bridge/CLI/icon/shims and raw Markdown/CSS/fonts are separate inputs | Existing one-build-per-OS artifacts serve E2E. Import reachability alone cannot excuse a build: asset relocation, loader transforms, generated constants, copy patterns and filesystem effects matter. Any webpack/Forge/tsconfig/assets/dependency change is full fallback |
| Dynamic/plugin/SDK | Native ESM plugin import deliberately lives in `.js` with `webpackIgnore`; the URL is resolved by Electron's custom protocol, with a dev-only IPC/blob fallback. Copilot `.js` loader carries lazy chunk magic comment, with FFI/runtime exclusions in webpack | Retain native-import tests, protocol/security tests and SDK static guard. Computed imports are explicit unknown edges; do not rewrite them into TS or interpret absent static import paths as unreachability |
| Generated/vendored/text | Codex generator writes generated types **and** runtime notification metadata; Framebriar manifest hashes source files; main and renderer ship Markdown/help/skill text. Main webpack copies JS bridge/CLI payloads | Generator input/output, metadata, vendored source/manifests, bridge JS, content under src and fixtures are full fallback. Existing schema drift/API checks remain. Top-level docs policy cannot be applied to src Markdown |

Authoritative project definitions: [vitest.config.ts](../../vitest.config.ts). `npm test` runs all five projects. `test:unit` runs only main/shared; it is not a replacement for the complete current unit job. Production `tsconfig.json` includes src and excludes test/QA files; webpack and script tools have additional inputs. A selector must use each tool's actual input universe rather than treating tsconfig membership as the complete repository graph.

## Edges that static imports miss

These are observed current contracts, not hypothetical exceptions:

- [test/global-setup.ts](../../test/global-setup.ts) checks Windows path validity, including untracked/ignored files, on teardown. A close-time failure must continue to affect exit status. Keep this setup in selected invocations; do not bypass it with a fresh minimal Vitest config.
- [test/setup-renderer.ts](../../test/setup-renderer.ts) provides a large global `window.clubhouse` mock with `platform: process.platform`, ResizeObserver and scrollIntoView substitutes. Individual tests override it; [TranscriptViewer.test.tsx](../../src/renderer/features/agents/TranscriptViewer.test.tsx) also provides IntersectionObserver. These tests do not test real IPC or browser observation. Any setup/mock change invalidates the cohort.
- Main project loads `test/standard-runtime-boundary.ts`, which deletes opt-ins to real runtime/model QA. Preserve that setup, opt-in boundaries and project identity. Existing root Electron/Monaco/ws aliases differ from integration's real ws and from packaged Electron. Passing Node/jsdom tests cannot substitute for the build/E2E boundary.
- [src/shared/ipc-channel-sync.test.ts](../../src/shared/ipc-channel-sync.test.ts) imports the preload API and reads handler/preload directories as text. There is no import edge from every scanned handler to the test. Computed settings keys and event-only/bidirectional channels also require explicit contract edges.
- [dispatcher-copy.test.ts](../../src/main/services/dispatcher/dispatcher-copy.test.ts) scans shown strings across **main, renderer, shared and preload**, plus help/instruction text. A renderer-only edit can fail a main-project test without any import relationship.
- [log-namespaces.test.ts](../../src/shared/log-namespaces.test.ts) scans non-test TS/TSX across src. [tailwind-theme-color-classes.test.ts](../../test/tailwind-theme-color-classes.test.ts) scans renderer source against index.css. Shard tests scan spec directories and read workflow/config text. Register these filesystem dependencies; do not assume a source-reader only tests its own imports.
- Test helpers, JSON/Markdown fixtures, snapshots, barrel exports, literal `require`, literal dynamic import, `vi.mock` factories, module resets and source-file reads contribute edges. Mock pruning is unsafe by default: some factories import actual modules, and an imported module can have side effects before a mock applies.
- OS edges include case-sensitive paths, Windows separators/drive letters/ConPTY, Darwin Cmd/menu/window chrome/spawn-helper, shell selection and login env, temp-file cleanup, and real watcher behavior. A path utility may normalize Windows input on Linux without proving Windows fs/process behavior. No OS can be dropped on the basis of that normalization test.

There are many filesystem calls in tests, most concerning temp fixtures rather than source dependency edges. A grep of `readFile` is a discovery aid, not a complete manifest or justification to run every filesystem test forever. Until their reads are classified, an unmodeled source-reader must force full fallback for actual skipping.

## Initial eligible production leaf: transcript duration formatter

**Exact candidate:** existing `src/renderer/utils/format.ts`, optionally accompanied by edits to its existing `src/renderer/utils/format.test.ts`, plus ordinary docs outside src. No `src/renderer/**` wildcard and no second production file. A test-only change to that exact direct test is the narrower companion cohort. It must not be generalized to arbitrary test files, fixtures or setup modules.

Observed source at the baseline:

1. `format.ts` is a single exported `formatDuration(ms: number): string`, with local arithmetic/string formatting and `Math.round`/`Math.floor`. It imports nothing, reads no platform/env/time/locale/files/IPC and has no module initialization effects.
2. The only observed direct production importer is `features/agents/TranscriptViewer.tsx`. Its direct test is `utils/format.test.ts` (4 cases). TranscriptViewer's test has 10 cases and explicitly expects `duration_ms: 30000` to display `30s`.
3. Runtime UI path: `format.ts` → TranscriptViewer → `states/RunInsets.tsx` → HeadlessAgentView, HeadlessRunFinished and QuickAgentGhost → renderer shells/App/Popout consumers. The utility is not isolated from application rendering merely because it has one production importer.
4. A local TypeScript AST inspection of imports/exports, literal dynamic imports/require and `vi.mock` paths, conservatively retaining type and mock edges, found a reverse closure of **259 source/test files** and reached App, PopoutWindow and plugin roots. This is an exploratory over-approximation, **not** a complete runtime graph: the resolver covered common relative source extensions, not all aliases/import types/assets/computed/source-reader edges. It is sufficient to reject a proposed selection of only the two direct test files. The implementation must regenerate its own complete graph/manifest on base and head; never use 259 as a permanent bound or a savings estimate.
5. Several parent tests replace TranscriptViewer with a stub. Keep them in a conservative selection rather than inferring an automatic exclusion from mock presence. `features/agents/states/format.ts` is a different module: it reexports shared session-display helpers and includes Date/locale/path formatting. It is **not** part of this allowlist.

This candidate is defensible for learning the shadow algorithm because the changed function has a simple auditable capability boundary, known direct behavioral tests and no native dependency. It is not a proven license to skip all other checks. A change that adds imports/exports, top-level statements, external globals, platform/env/time/locale/IPC/fs/network access, eval/Function, dynamic resolution or global mutation must fail eligibility. Compare an approved AST/capability shape on both trees; “still imports nothing” alone does not prove purity. API/signature changes or function removal also fall back.

## Concrete shadow output and retained checks

For a qualifying diff, report the **candidate** unit selection below, while the actual workflow continues running its entire existing Linux/Windows matrix. This is a conservative first cohort; projected unit reduction is confined to main tests outside the retained sentinels, not to build/E2E or OS coverage.

| Retained unit scope on **both Linux and Windows** | Reason |
|---|---|
| Whole `renderer` project, using the existing config/setup | Keeps direct formatter, TranscriptViewer and transitive consumer tests, including App/Popout/plugin/UI behavior; avoids prematurely pruning mock or barrel edges |
| Whole `shared`, `preload`, `integration` projects | Keeps source readers, bridge/channel shape, real-ws protocol contracts, shard/workflow/asset guards and existing globally configured checks. Existing explicit harness opt-ins remain off |
| Main `src/main/services/dispatcher/dispatcher-copy.test.ts` | Known source-tree read edge from changed renderer strings |
| Main `src/main/ipc/index.integration.test.ts` | Existing end-to-end-in-process preload/handler contract; despite its name it belongs to main project |
| Main `src/main/util/windows-pty.test.ts`, `src/main/services/pty-manager.test.ts`, `src/main/services/file-watch-service.test.ts`, `src/main/services/auto-update-apply.test.ts`, `src/main/services/auto-update-apply-windows.test.ts` | Explicit OS/process/watcher/update sentinels; many mocks and platform skips, so preserve job/OS identity and report skipped cases accurately |
| Every additional source-reader or reverse-closure test discovered by the implementation | The table is a minimum. Unresolved reads/paths/aliases force full fallback, never silently omit the test |

Use separate project-scoped invocations (or a supported pinned-Vitest API selection keyed by `(project, canonical file)`) so `--project main` cannot accidentally filter away renderer/preload/shared tests. Preserve teardown, reporters, failure exit codes and all selected files exactly once. A project union is a file list, not an intersection of multiple positional filters. A zero-match sentinel is an error; no blanket `--passWithNoTests` may hide a miss.

Retain these existing non-unit checks and their original trigger conditions in the **candidate** plan as well as in actual shadow CI:

- Linux ESLint, workflow lint, Codex drift, typecheck + coverage ratchet + API compatibility gate; dependency preflight and Windows-path/denylist planning checks when currently selected.
- The existing Linux and Windows builds and **all** existing E2E/Annex/chat/stable-mode/Classic shard lists. Do not infer feature coverage from test filenames or replace explicit lists with count sharding. Preserve trace/JUnit uploads and Windows packaged runtime evidence.
- Existing SDK static packaging guard on its selected OSes; Linux package/native/glibc checks when currently selected. No change to native setup, security or sandbox posture.
- Current macOS pause, full-ci and manual override semantics exactly as they stand. If macOS jobs are selected under existing policy, retain their full current coverage; the proposed leaf does not justify removing native checks or resuming the pause. Skipped Mac work remains a coverage gap, not cross-platform acceptance.

**No test has been selected away by this document.** The selector helper may choose an even more conservative shadow set, especially full fallback until source-read edge accounting exists. The scope above is intentionally broader than a direct import closure. It offers no measured speedup claim.

## Contract to the selector helper

1. Anchor push comparison to the actual `before` and head, PR comparison to base/head/merge-base semantics matching current policy. Record all source SHAs and checkout/merge identity. Missing/zero/unavailable base, ambiguous merge, rename/delete/addition, case-only path change, symlink/submodule, unreadable tree or unknown status → full fallback.
2. Require every non-doc changed path to be in the two exact eligible paths above. Package/lock/workflow/selector/config/setup/mock/assets/generated/vendor/main/shared/preload/native changes, mixed feature edits and src content → full fallback. Do not silently extend eligibility when a file is moved or a new formatter is added.
3. Build graph/contract manifests from **both** base and head; union dependency closures and added/removed edge effects. Record resolution/tool version and hashes of configs, allowlist and source-read manifests. Include TS runtime and type edges separately, exports/barrels, CommonJS/JS, literal dynamic imports and non-import asset/test edges. Unknown computed edges require an explicit stable boundary or fallback.
4. Emit eligibility reason, exact changed-file statuses, proposed project/file/test identities, retained mandatory checks, every fallback reason and an explanation path from each selected test to the changed leaf. A sampled/partial graph or absent evidence is not a successful selection.
5. Compare the proposed selection with the unchanged baseline's executed results on the **same exact head and each OS**. A failed omitted test is a selection miss until investigated; distinguish flakes, setup failures, cancellation and skipped tests. Passing excluded tests do not establish fault detection.
6. Validate the algorithm with controlled mutations of the formatter's rounding/minute/hour branches and display output; confirm direct and consumer tests are proposed and detect the relevant faults. Also test guard failures: new import, new side effect/global access, renamed/deleted file, shared type edit, setup change, dynamic import, unknown base and unresolved source-reader. These are proposed future bounded checks, not tests run in this lane.
7. Keep the shadow reporter advisory, with no job `if`, shard list, status requirement or workflow trigger consuming its result. Enable actual skipping only after an independently reviewed edge manifest, exact-head Linux/Windows shadow evidence, agreed false-negative disposition and a separate policy change. No arbitrary number of green runs proves absence of misses.

Parent coordination: the early direct-import candidate and its broad reverse closure were reported to the Orchestrator for relay to the selector helper. The helper decides implementation/order; eligibility expansion, unresolved boundary conflicts and any activation remain outside this documentation task.

## Future refactors that would support stronger selectivity

- Extract import-free presentation functions into a deliberately side-effect-free package/module boundary with an enforced capability/import rule and behavioral consumer contracts. Keep locale/time/OS/path formatting separate. Do not combine the two distinct `format.ts` modules just to make selection easy.
- Split UI shells/plugin registries from data/view-model contracts; prevent lower-level utilities/stores from acquiring UI singleton/barrel imports. Establish an actual acyclic module graph before using a directory as a cohort.
- Generate typed IPC/bridge metadata from a checked-in channel contract and give source-scanning tests explicit dependency manifests. Keep behavioral invoke/handler checks; generated declarations alone do not establish runtime wiring.
- Declare fixture/source/text/copy/glob dependencies alongside tests/tools. Track generated-code inputs and outputs, package optional dependencies/native artifacts, platform/environment contracts and test setup versions in the selector's graph.
- Separate pure logic tests, mocked adapters and real OS/native integration in explicit test projects over time. Preserve current coverage during migration; this proposal does not relabel mocked tests as native proof or remove work based on anticipated refactors.

## Evidence and limits

Inspection used tracked source/config/tests, read-only searches and a local AST traversal using the existing root TypeScript installation. No install, product change, app/native execution, test run, hosted request/run or job-history collection was needed. The exploratory graph is not saved as production selector code. Documentation diff checks verify formatting only; independent review and algorithm/runtime validation remain outstanding. No release-related workflow or artifact was changed.
